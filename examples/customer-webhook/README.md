# Customer webhook receivers

SignalStack customer webhooks are outbound, at-least-once notifications. They are unrelated to inbound
provider callbacks and never authorize a SignalStack mutation. The TypeScript and Python receivers use only
their standard runtimes and implement the frozen protocol directly.

Configure a version-to-secret map from the one-time endpoint create/rotation responses, then start one local
receiver:

```bash
export SIGNALSTACK_WEBHOOK_SECRETS_JSON='<JSON map from secret version to whsec value>'
npx tsx examples/customer-webhook/receiver.ts

# Or:
python3 examples/customer-webhook/receiver.py --port 8787
```

The map lets a receiver retain the previous version during the 24-hour rotation overlap while selecting the
key named by `X-SignalStack-Secret-Version`. A single-key setup may instead set
`SIGNALSTACK_WEBHOOK_SECRET` and `SIGNALSTACK_WEBHOOK_SECRET_VERSION`. Do not put either value in source,
URLs, logs, or browser state.

Both examples:

1. read the exact raw request bytes and duplicate-preserving raw headers;
2. require one timestamp, signature, secret-version, event-ID, event-type, and delivery-ID header;
3. enforce a five-minute timestamp tolerance;
4. compute HMAC-SHA-256 with the 32 decoded `whsec_` bytes over
   `signalstack/customer-webhook-signature/v1\0 + timestamp + "." + raw_body`;
5. compare fixed-size digests in constant time before JSON parsing;
6. validate header/body event identity, then claim the event ID before effects.

The in-memory event-ID set is deliberately small example code. A production receiver must replace it with an
atomic durable unique claim such as `INSERT ... ON CONFLICT DO NOTHING`; process memory cannot deduplicate
retries across restarts or replicas. Return any `2xx` only after that claim and required effects commit.

The receiver binds to `127.0.0.1`. Put it behind production HTTPS before configuring a SignalStack endpoint;
the platform rejects non-public or unsafe production URLs and follows no redirects.

[`golden-vector.json`](golden-vector.json) is public test material, not a deployable secret. It is generated by
[`generate-golden-vector.ts`](generate-golden-vector.ts) through the production signer, and
`npm run examples:check` executes both receiver implementations against its exact newline-terminated body.
