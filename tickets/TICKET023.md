# TICKET023 — Human-gated production identity, tenant routing, RLS, and gate integrity

- **Status:** Partially complete (2026-07-12) — identity, RLS, and composite tenant-integrity items landed with milestones M1/M2 (built-in local auth replaced the Clerk plan; forced RLS + composite tenant foreign keys + fail-closed tenant context are database-enforced and tested). Remaining scope: trusted provider-account/number webhook tenant routing (M4/M6), webhook retry policy review, live-test/lookup operator-token provisioning, and the human-reviewed integrity-manifest anchoring.
- **Priority:** P1
- **Blocked by:** Human-approved webhook-routing, operator-secret, and protected-gate decisions

## Goal

Complete the production-only tenant boundary after explicit human approval. The settings consolidation is documentation/UI cleanup and must not be treated as production enablement.

## Scope

- Verify Clerk subjects and sessions, then resolve exactly one active tenant membership and role; coordinate with TICKET021.
- Exercise database RLS through a production-shaped non-superuser role with DATABASE_RLS_ENFORCED=true, including cross-tenant denial tests, and make a missing tenant session variable fail closed rather than bypass policies.
- Add composite tenant foreign keys for tenant-owned relationships (including campaign recipients, messages, contacts, templates, and campaigns) after auditing legacy rows, so the database cannot store cross-org relationship corruption that repositories currently filter defensively.
- Route signed provider webhooks through trusted provider-account/phone-number ownership metadata. Unknown or ambiguous mappings must fail closed before persistence or domain mutation.
- Configure and verify the provider webhook retry policy explicitly for HTTP status failures and timeouts; do not assume `Retry-After` causes redelivery under provider defaults.
- Before enabling the isolated live-test SMS path, provision and rotate a 32-256 character `LIVE_TEST_SMS_OPERATOR_TOKEN` through an approved server-side secret manager. The deterministic demo session is not operator identity, and the token must not enter source control, logs, browser configuration, or stored audit metadata.
- Before enabling paid single-contact Twilio Lookup, provision and rotate a separate 32-256 character `LIVE_LOOKUP_OPERATOR_TOKEN`, restrict who may supply its dedicated request header, and set an operator-owned usage/cost cap. The deterministic demo session is not authorization for a paid provider request, and the token must not enter source control, URLs, browser-delivered configuration, logs, or persistence.
- Have a human review and update the protected integrity gate so a missing manifest fails instead of self-authorizing new hashes, and anchor the manifest itself so changing expected hashes cannot silently authorize modified gate files.

## Out of scope

Real secrets, live-feature flag changes, destructive or production database operations, live messages, unattended edits to integrity-protected files, and new settings pages.

## Acceptance criteria

- [ ] Missing, expired, wrong-tenant, inactive-membership, and insufficient-role sessions are denied.
- [ ] A production-shaped database role cannot read or mutate another tenant's rows.
- [ ] A valid signed webhook resolves exactly one organization; unknown or ambiguous ownership returns a safe 4xx with no mutation.
- [ ] Provider webhook URLs have a reviewed retry count/policy for `4xx`, `5xx`, connection, and read-timeout failures, with signature validation tested against connection-override fragments.
- [ ] A human provisions and verifies the live-test operator token through production secret management, confirms that public readiness exposes only counts/last-four hints, and exercises the bounded timeout plus idempotent `202` retry path without a second provider call.
- [ ] A human provisions the separate paid-lookup operator token and cost cap, verifies missing/mismatched authorization fails before provider fetch, and confirms provider phone mismatches fail without writing a contact.
- [ ] Missing or modified integrity-manifest evidence fails closed; any protected-gate change is human-reviewed and the integrity manifest is deliberately re-generated by a human.
- [ ] npm run production-auth:check, targeted tenant-routing/RLS tests, npm run contracts:check, and npm run validate pass in the approved environment.

## Risks

An auth fallback, public demo session, missing/weak operator token, uncapped paid lookup, superuser test connection, demo-org webhook fallback, or stale integrity hash can create a false production-ready signal. Keep all production flags off until every acceptance item is evidenced.
